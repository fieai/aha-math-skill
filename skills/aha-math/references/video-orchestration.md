# 视频编排优化规则

这份参考沉淀三类经验：

- 用户反馈：不要跳步骤，也不要把一个关系拆成多个重复镜头。
- HyperFrames：先做终态布局，再加动画；用 lint/inspect 思维验证视频。
- fogsight-v5：LLM 只产 draft，时间轴、校验和结构完整性由代码或模板控制。

## 1. 镜头必要性检查

每个镜头都必须引入一个新信息、新动作或新结论。

写完 storyboard 后逐镜头问：

```text
这一镜头解决了什么新问题？
它和前一镜头是否都在讲同一个关系？
能不能合并成一个更清楚的动作？
删掉它会不会让孩子看不懂？
```

如果两个连续镜头都在讲同一条关系，优先合并。

例：减法题里这两个镜头应合并：

```text
镜头 A：减法是一整条拿走一段
镜头 B：减数 + 差 拼回被减数
```

合并为：

```text
镜头：蓝色减数 + 绿色差 拼回金色被减数
```

旁白：

```text
被减数可以分成两段：一段是减数，一段是差。把这两段合起来，还是原来的被减数。
```

## 2. 不要把中间过程当主标题

标题和开场必须对准用户原题。

错误：

```text
为什么被减数是 500
```

这个只是中间过程，不是原题目标。

正确：

```text
减法填空：求被减数和差
```

开场先呈现：

```text
被减数 + 减数 + 差 = 1000
减数 = 206
被减数 = ?
差 = ?
```

再进入中间解释：

```text
为什么先求被减数？
为什么 1000 是两个被减数？
```

## 3. 低龄题优先“小数字代入法”

当用户说“讲复杂了”“绕”“给小朋友看”时，优先尝试小数字代入，而不是结构模型。

例：加法题

```text
2 + 3 = 5
5 比 2 多 3
5 比 3 多 2
```

再套回大数：

```text
和比一个加数多 2027 → 另一个加数是 2027
和比另一个加数多 2025 → 一个加数是 2025
```

判断标准：

- 若小数字例子能直接说明关系，优先用小数字。
- 若小数字仍解释不了关系，再用实物/长条/天平。
- 不要同时堆小数字、实物、公式三套模型，容易变复杂。

## 4. 先终态布局，再加动画

借鉴 HyperFrames 的 Layout Before Animation：

1. 先写每个镜头最清楚的一帧，也就是所有关键元素已经摆好的终态。
2. 确认这帧能独立说明镜头目标。
3. 再添加入场、移动、强调和出场动画。

不要从动画起点开始设计画面。起点经常是透明、缩小、屏外，不能判断最终布局是否清楚。

Manim 执行规则：

```text
先创建终态 VGroup
arrange / next_to / fit_content
再 self.play(FadeIn / Transform / Create)
最后 caption + wait 触发布局检查
```

## 5. LLM 只产教学 draft，确定性部分交给代码

借鉴 fogsight-v5：

- LLM 负责：受众判断、误解点、具体动作、旁白、镜头目标。
- 模板/代码负责：场景顺序、时长、布局检查、字体检查、渲染验证。
- 不要让 LLM 随意决定大量精确时间轴；用固定节奏即可。

推荐 draft 结构：

```json
{
  "audience": "小学低年级",
  "problemGoal": "求被减数和差",
  "coreMisconception": "不知道为什么 1000 是两个被减数",
  "visualModel": "长条切分",
  "scenes": [
    {
      "goal": "说明减数 + 差 = 被减数",
      "visualAction": "蓝色减数和绿色差拼回金色被减数",
      "childNarration": "拿走的那段加上剩下的那段，正好拼回原来的整条。",
      "mathTranslation": "减数 + 差 = 被减数",
      "necessity": "关键镜头，不能删"
    }
  ]
}
```

## 6. 检查清单

写完 storyboard 后必须检查：

```text
标题是否对准原题，而不是中间步骤？
每个镜头是否有新信息？
有没有两个镜头在讲同一个关系？
最难的一步有没有动作画面？
有没有先给小例子，再套大数的可能？
能否删掉一个镜头而不损害理解？
结尾是否回到用户原题的填空/问题？
```

用户指出“复杂”“多余”“跳步骤”时：

```text
先改分镜，不要直接改视频。
优先删镜头或合并镜头。
优先降低解释模型数量。
确认主问题和中间过程没有倒置。
```
